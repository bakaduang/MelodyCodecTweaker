# QQ 音乐 / 网易云音乐单耳合并 preview.4

版本：`2.5.0-preview.4`（versionCode 31）。面向当前 Enco X3 / Find X9 Ultra / Android 16 组合，适配 QQ 音乐与网易云音乐的播放器 PCM。后端限定 Android 16、arm64 和精确音频 ABI；未知入口保持原音频。

## 安装

1. 覆盖安装本版 APK。
2. 在 LSPosed 中保留原四个作用域：无线耳机、蓝牙、无线设置、系统设置。
3. 新增 QQ 音乐（`com.tencent.qqmusic`）和网易云音乐（`com.netease.cloudmusic`）。两款 App 的播放子进程也需要加载模块。
4. 重启手机，使蓝牙、无线耳机和两个播放器都加载新代码。
5. 保持原版耳机佩戴检测开启，在官方耳机面板确认开启“单耳自动合并声道”。

沿用 preview.1–3 的本地测试签名，可以覆盖同签名 APK。升级后的控制协议为 v2，旧进程的系统单声道状态不能作为新后端的成功证明，安装后需完整重启。

## 混音位置与控制

此前 QQ 音乐 DIRECT 输出中，系统单声道出现返回成功但读回关闭，而且 DIRECT 不参与标准 MIXER 的 mono 处理。本版改为在播放器向 AudioTrack 提交共享 PCM 时，把每个立体声帧变为：

```text
M = (L + R) / 2
输出左声道 = M
输出右声道 = M
```

PCM 沿原路径继续输出，蓝牙硬件编码接收到的是已经合并的内容。处理不修改输入文件、不录音，不改变采样率或蓝牙码率设置。正常运行不调用 `setMasterMono(true)`；旧版持有的临时系统单声道恢复记录会先处理。

原生代码使用 LSPosed Native Hook API，严格匹配 `AudioTrack::set`、`releaseBuffer` 等符号，从成功初始化中取得格式、声道与用途，不读取猜测的 AudioTrack 成员偏移。仅处理媒体用途、立体声及六种标准 PCM 格式。压缩编码、静态共享音轨和未知 ABI 保持透传。

路由控制先依据新鲜的默认媒体输出与轨道的显式设备选择；收到实际设备回调后，以该轨道的回调为准。没有设备回调的轨道尚不能逐条排除系统按 App 分流，因此当前不能把默认路由校验表述为所有音轨都已获得实际路由证明。所提供 QQ 音乐反馈中，系统 App 重定向功能为关闭。

| 情况 | 行为 |
| --- | --- |
| 两侧已确认，仅左耳或仅右耳佩戴 | 短暂防抖后允许播放器合并 PCM |
| 左右单耳互换，连接仍相同 | 保持合并，更新佩戴侧标签 |
| 双耳或均未佩戴 | 停止合并，保留原声道 |
| 断开、通话、多输出或输出未知 | 停止合并 |
| 蓝牙控制消息停止更新 | 原生代码在 4 秒租约到期后透传 |
| 未启用播放器作用域 / 未重启播放器 | 显示等待播放器或入口不可用 |
| 入口已安装但没有音频帧 | 显示等待播放，不能显示已合并 |
| 本次会话确实处理到 PCM 帧 | 显示“左右声道已合并” |

两个播放器共用处理逻辑，主进程与播放子进程各自持有短租约。播放器广播只报告状态与计数；蓝牙侧依据佩戴和路由决定何时合并，控制广播校验蓝牙身份。开关继续按耳机保存，开启和关闭继续显示确认弹窗。

## 验证

分别在 QQ 音乐和网易云音乐播放附带的 `stereo-channel-check.wav`（左侧一个长音、右侧两个短音）：

1. 仅戴左耳，开启后应同时听到长音和两个短音；仅戴右耳也应如此。
2. 关闭功能，对比原来的声道；重新戴双耳，确认保留原始立体声。
3. 锁屏后摘戴、两款播放器互换、断开重连，再检查状态。

PCM 算法、控制协议与构建可以在本机验证；两款 App 是否命中该 ROM 的原生入口、听音效果与连接切换仍需真机确认。当前电脑未连接 ADB 设备，本地测试不能代替这些检查。

诊断页新增“播放器声道合并”。若入口不可用，反馈中的 `MelodyPcmMono` 日志提供原生入口安装结果；`mono.pcm.backend` 记录本次 generation 和实际处理帧数。`audio-state.txt` 保留输出快照。

依据见 [第一批反馈分析](single-ear-feedback-20260910.md) 和 [QQ 音乐 DIRECT 路径分析](single-ear-feedback-221015.md)。构建使用 `:app:testDebugUnitTest` 与 `:app:assembleRelease`；另对纯 C++ PCM 处理做本机测试。提供签名 APK、未签名 APK和测试音，本地测试签名与正式发布签名不同。
