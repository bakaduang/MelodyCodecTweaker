# 单耳自动合并声道预览版

此文保留 preview.3 系统单声道诊断版的历史说明。当前功能与安装要求以 [README 的单耳自动合并说明](../README.md#单耳自动合并声道)为准。

版本：`2.5.0-preview.3`（versionCode 30，诊断版）。首个验证目标是 OPPO Enco X3、Find X9 Ultra / 系统 16.0.10，以及无线耳机 App 16.8.3。

2026-09-10 的三个反馈包确认 preview.1 存在间歇性 `audio_write_failed`，且实际使用 Qualcomm A2DP offload。用户进一步确认同一播放场景中，手动开启手机系统的单声道也无法补全缺失声道。此前一次重启后有效的反馈不足以证明适配稳定。

**preview.3 用于补充诊断证据，未修复实际混音。** 它记录音频调用返回码、调用前后读回和耗时，反馈包加入音频服务快照，面板改为“系统单声道已开启 · 混音效果待确认”。沿用 preview.2 的 LE Audio 风格确认弹窗，开启和关闭都需要确认。

安装后，保留原来的四个 LSPosed 作用域，并重启手机，让无线耳机和蓝牙进程加载新代码。在官方耳机面板的蓝牙音质区域打开“单耳自动合并声道”，并在弹窗中确认。它默认关闭，按耳机保存；原版耳机的佩戴检测也需要保持开启。

| 当前情况 | 预期行为 |
| --- | --- |
| 左右耳都已确认，仅左耳或仅右耳佩戴 | 短暂防抖后请求系统单声道，声音效果需另行验证 |
| 双耳佩戴或均未佩戴 | 恢复用户原来的音频设置 |
| 任一侧尚未收到本次连接的状态 | 等待状态，不猜测未佩戴 |
| 切换到其他音频设备、进入通话或检测到多个输出 | 暂停自动合并并恢复 |
| 宿主进程停止心跳 | 15 秒租约到期后恢复 |
| 蓝牙进程重新启动 | 先处理遗留恢复记录，再允许新的接管 |
| 用户手动修改系统单声道设置 | 保留新选择，暂停当前会话的自动控制 |

需要重新接管时，可以关闭再打开本功能。连接和控制协议重建都会重新确认耳状态，避免沿用旧连接中的另一侧。

合并作用于系统音频引擎，因此合并期间会临时影响全局音频输出。检测到多个输出时会暂停，但它仍不是按设备隔离的音频效果。实现调用蓝牙进程中的 `AudioSystem.setMasterMono`，通过回读确认状态；不修改用户保存的 `Settings.System.master_mono` 偏好。接管前先提交恢复记录，确认恢复后才清除。

本版沿用 Release 的 LHDC 治理器配置，不包含 Debug 变体的固定码率 A/B 行为。当前后端依赖系统混音能力；切换可能重建播放路径，LHDC / LE Audio 的实际声音效果仍需验证。AudioSystem 标志读回不能证明 PCM 内容完成混合。

**安装包签名**

本地提供的可安装 APK 沿用 preview.1 的测试密钥，可覆盖此前提供的同签名测试 APK。它可能无法直接覆盖其他签名的正式版或重新签名版。另附未签名 Release APK，持有原密钥时可重新签名后升级。

建议按以下顺序验证：

1. 打开原版佩戴检测和本功能，先戴双耳，确认面板能显示双耳状态。
2. 播放附带的 `stereo-channel-check.wav`。测试音循环播放“左声道单个长音”和“右声道两个短音”。
3. 仅戴左耳，应同时听到长音和两个短音；仅戴右耳也应如此。
4. 另一只分别放回仓内和放在桌上，检查都能识别单耳。
5. 重新戴双耳，检查恢复原音频设置；再关闭功能，对比开关前后的效果。
6. 锁屏并关闭耳机面板后重复摘戴；随后验证断开重连、LE Audio 切换和模块总开关关闭。

模块诊断页新增“左右耳佩戴 Hook”“自动单声道桥”“单耳自动合并状态”。如果没有生效，先记录这三项和官方面板摘要；再通过原有“开始记录问题 → 复现 → 生成反馈包”流程反馈。状态中 `known` 为本次连接确认过的侧，`ear` 为入耳侧，`box` 为在仓侧（左为 1、右为 2）。

本次排查只需保持原播放器、编码和单耳场景，开始记录后开启一次模块开关，等约 5–10 秒，保留开关开启和音乐播放状态生成反馈包。请保留当前失败现场，以便 `audio-state.txt` 捕获到对应输出。生成的 `summary.txt` 和 `mono.audio.write` 事件均应显示 preview.3。

新反馈包含：

- `mono.audio.write`：每次实际写入的 `target`、`before`、`after`、`saved`、返回 `status`、异常、调用耗时与 `write_at_ms`。它使用现有控制器的读回，不额外请求混音或重试。录制开始时可能重放最后一次写入事件，原始写入时刻以 `write_at_ms` 为准。
- `audio-state.txt`：生成反馈时读取当前用户的系统单声道偏好、A2DP offload 属性、AudioPolicy 和 AudioFlinger。各段分时读取，服务不可用或超时会保留错误；这些数据不包含音频采样。
- `state.json` 补齐三项自动单声道状态；持续日志补充音频策略、混音服务和 A2DP offload 标签。

本版没有切换硬件卸载属性，也没有改动音频控制策略。具体分析见 [2026-09-10 反馈分析](single-ear-feedback-20260910.md)。

开发验证采用 `:app:testDebugUnitTest` 与 `:app:assembleRelease`。项目原有 `NativeLhdcMemoryPatchTest.debugBuildIdentifiesFixed1000AbEvidenceMode` 固定断言 Debug 配置，因此不能将整个现有测试集直接用于 Release 单元测试任务。新增测试覆盖部分状态、重连与并发消息顺序、旧进程租约，以及音频接管和恢复故障。

本地工具与反编译文件位于已忽略的 `build/` 中；Android SDK 路径在已忽略的 `local.properties` 中。构建使用 Gradle 8.13 和本机 NDK 28.2.13676358；本地 NDK 覆盖通过 `build/local-build.init.gradle` 提供，不改变仓库默认构建配置。
